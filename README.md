# amazonsan — повна стартова версія каталогу

Україномовний адаптивний каталог товарів з Amazon. Проєкт підготовлений для розгортання на Cloudflare Pages і використання Supabase як бази даних, системи входу та сховища фото.

## Що вже реалізовано

- Адаптивний інтерфейс для смартфонів, планшетів і комп'ютерів.
- 19 основних категорій і понад 80 підкатегорій.
- Каталог, пошук за назвою/описом/категорією/SKU, фільтри та сортування.
- Картки товарів і детальна сторінка товару.
- Позначки «Новинка» та «Популярне».
- Реєстрація та вхід через email/пароль і Google (після налаштування провайдера в Supabase).
- Обране користувача.
- Адмінпанель: створення, редагування, видалення, чернетки/публікація товарів.
- Завантаження зображень у Supabase Storage.
- Імпорт та експорт товарів у JSON.
- Ціна в гривнях та початкова ціна в USD.
- Favicon та іконка для мобільного ярлика (SVG-заготовки).
- RLS-політики в SQL для захисту даних.

## Важливо перед запуском

ZIP — це готовий код проєкту, але не вже опублікований сайт. Для реальної роботи акаунтів, спільної бази товарів, обраного та адмінпанелі треба один раз створити Supabase-проєкт, виконати SQL і додати публічні ключі у змінні середовища Cloudflare. Я не можу входити у твої акаунти замість тебе. Не надсилай мені паролі або секретні ключі.

Демонстраційні товари — приклади для вигляду сайту. Їх потрібно замінити перевіреними товарами та реальними фото/характеристиками. Проєкт не імпортує весь каталог Amazon автоматично: для автоматичного імпорту потрібен дозволений API/фід та відповідні права.

## 1. Локальний запуск (за бажанням)

Потрібен Node.js 20 або новіший:

```bash
npm install
cp .env.example .env
npm run dev
```

Без Supabase відкриється демонстраційний режим. Дані демо-режиму не синхронізуються між пристроями.

## 2. Налаштування Supabase

1. Створи проєкт на https://supabase.com/.
2. Відкрий SQL Editor.
3. Скопіюй весь вміст `supabase/schema.sql` і виконай його.
4. В Authentication → Providers увімкни Email. Для Google увімкни Google provider та налаштуй OAuth Client у Google Cloud; додай callback URL, який покаже Supabase.
5. У Supabase → Project Settings → API скопіюй Project URL та anon/public key.
6. У Cloudflare Pages → Settings → Environment variables додай:
   - `VITE_SUPABASE_URL` = Project URL
   - `VITE_SUPABASE_ANON_KEY` = anon/public key
7. Перезапусти deployment після додавання змінних.
8. Зареєструй власний користувацький акаунт на сайті.
9. У Supabase → SQL Editor виконай запит, замінивши email на свій:
   ```sql
   update public.profiles set is_admin = true where email = 'твій-email@example.com';
   ```
10. Вийди та увійди знову. З'явиться панель адміністратора.

**Ніколи не додавай `service_role` key у фронтенд чи змінні `VITE_*`.** Для сайту використовується лише anon/public key; доступ контролюється RLS.

## 3. Публікація на Cloudflare Pages

1. Розпакуй ZIP.
2. Створи Git-репозиторій (GitHub) і завантаж файли проєкту.
3. У Cloudflare Dashboard відкрий Workers & Pages → Create → Pages → Connect to Git.
4. Обери репозиторій.
5. Build command: `npm run build`
6. Build output directory: `dist`
7. Додай змінні Supabase з попереднього розділу до Production та Preview.
8. Натисни Deploy.

Можна також використати інший спосіб публікації, але Git-інтеграція зручніша для наступних оновлень.

## 4. Заміна іконки сайту

Заміни `public/favicon.svg` і `public/icon.svg` своїми файлами з такими самими назвами, після чого зроби новий deployment. Для найкращої сумісності можна використати PNG 512×512 для мобільного ярлика.

## 5. Дані та безпека

- Адмін-права надаються вручну через SQL після реєстрації.
- Користувач може читати й змінювати лише власні записи обраного.
- Публічні відвідувачі бачать тільки опубліковані товари.
- Створювати, змінювати та видаляти товари можуть лише адміністратори.
- Фото доступні публічно, завантажувати/видаляти їх можуть лише адміністратори.
- Увімкни резервне копіювання Supabase, коли воно доступне на обраному тарифі, і регулярно експортуй каталог JSON.

## 6. Межі поточної версії

- Немає кошика, оформлення замовлення, платіжного шлюзу чи доставки — сайт зараз каталог, як і було погоджено.
- Немає автоматичного синхронізованого імпорту з Amazon.
- Не реалізовано email-розсилки, аналітику та багатомовність.
- Умови/політика конфіденційності та контакти потрібно заповнити власними даними перед публічним запуском.
- Для Google OAuth потрібне налаштування в сторонніх кабінетах.

## 7. Підтримка

Після розпакування надішли скриншот того екрана, де зупинився. Проведу по кроках. Не публікуй паролі, OAuth secrets або service-role ключі.

## Нові інструменти залучення відвідувачів (поточна версія)

- Блоки «Новинки тижня», «Хіти продажів», «Акції та знижки», «Рекомендуємо» та «Нещодавно переглянуті» на основі позначок товарів.
- Позначення товарів: наявність/відсутність, новинка, популярне, хіт продажів, знижка зі старою та новою ціною, редакційний вибір, рекомендований та ексклюзивний товар, товар дня.
- Порівняння до чотирьох товарів та локальна історія нещодавніх переглядів.
- Базовий «Розумний підбір» за категорією, бюджетом та текстовою характеристикою. Це локальний фільтр каталогу, а не AI-модель.
- Перемикачі видимості основних промоблоків у налаштуваннях адміністратора. У цій версії вони зберігаються у локальному сховищі браузера адміністратора; для синхронізації між пристроями потрібне підключення таблиці `site_settings`.
- SQL-підготовка таблиць для модерації відгуків, підписок на сповіщення про ціну/наявність, налаштувань сайту та промокампаній.

## Що ще потребує окремого підключення або реалізації

- Автоматичне надсилання сповіщень про зміну ціни/наявність: потрібен email-провайдер або Supabase Edge Function і згода користувача. Таблиця підписок підготовлена, але форма підписки та відправник листів ще не підключені.
- Відгуки: схема таблиці та модераційні RLS-політики підготовлені; публічна форма, кабінет автора та інтерфейс модерації ще потребують реалізації. Не показувати неперевірені відгуки як підтверджені покупки.
- AI-консультант, генерація опису за фото та пошук за зображенням: потрібен окремий AI/API сервіс, ключі зберігати лише на сервері/Edge Function; ці функції не активовані в цій збірці.
- Персональні рекомендації на основі поведінки, рекламні кабінети, платне просування, партнерська аналітика та керування промокампаніями: таблиці/концепція передбачені частково, повний робочий інтерфейс та інтеграції ще не реалізовані.
- Розширені банери брендів, FAQ, відеогалерея та автоматичні листи потребують окремих екранів і перевірки інтеграцій.

## Оновлення бази даних

Перед використанням нових полів товарів та додаткових таблиць виконай повний оновлений `supabase/schema.sql` у Supabase SQL Editor. Скрипт містить `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` для наявної таблиці товарів. Після оновлення перевір RLS та Storage-політики у власному Supabase-проєкті.

Нова версія архіву не означає автоматичного оновлення чинного сайту. Спочатку перевір її у окремому preview-середовищі; не замінюй production deployment до перевірки збірки та погодження власника.
